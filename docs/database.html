ER 図

テーブル定義

lists — ルームテーブル

カラムDrizzle 型DB 型制約説明
id text("id") TEXT PRIMARY KEY crypto.randomUUID() で生成
createdAt integer("created_at", { mode: "timestamp" }) INTEGER NOT NULL Unix 秒で保存。Drizzle が Date に自動変換
name text("name") TEXT nullable ルーム名。未設定も許容

items — 落とし物テーブル

カラムDrizzle 型DB 型制約説明
id text("id") TEXT PRIMARY KEY crypto.randomUUID() で生成
listId text("list_id").notNull().references(()=>lists.id) TEXT NOT NULL, FK → lists.id
索引: items_list_id_idx		 所属ルームの外部キー
comment text("comment") TEXT nullable 説明文（最大 1000 文字: API 側バリデーション）
imageUrl text("image_url") TEXT nullable /api/images/{listId}/{uuid}-{filename} 形式
createdAt integer("created_at", { mode: "timestamp" }) INTEGER NOT NULL 登録日時
deletedAt integer("deleted_at", { mode: "timestamp" }) INTEGER nullable ★ ソフトデリートマーカー。null = 有効、Date = 削除済み
Drizzle スキーマ全文 (src/server/db/schema.ts) 
import { index, integer, sqliteTable, text } from "drizzle-orm/sqlite-core";

export const lists = sqliteTable("lists", {
  id:        text("id").primaryKey(),
  createdAt: integer("created_at", { mode: "timestamp" }).notNull(),
  name:      text("name"),
});

export const items = sqliteTable(
  "items",
  {
    id:        text("id").primaryKey(),
    listId:    text("list_id").notNull().references(() => lists.id),
    comment:   text("comment"),
    imageUrl:  text("image_url"),
    createdAt: integer("created_at", { mode: "timestamp" }).notNull(),
    deletedAt: integer("deleted_at", { mode: "timestamp" }),
  },
  (table) => [index("items_list_id_idx").on(table.listId)],
);

型マッピング

Drizzle 定義SQLite DB 型TypeScript 型備考
integer({ mode: "timestamp" }) INTEGER Date | null Drizzle が Unix 秒 ↔ Date を自動変換
text() TEXT string | null UUID, URL, ルーム名など
.notNull() NOT NULL string / Date（non-nullable）
現在時刻の取得は new Date() を使う。Math.floor(Date.now() / 1000) は NG —— Drizzle がすでに秒変換するため二重変換になる。

ソフトデリート規約

items テーブルのみ適用。lists は物理削除（R2 画像の連鎖削除が必要なため）。

操作Drizzle コード
削除 .set({ deletedAt: new Date() })
復元 .set({ deletedAt: null })
通常取得（削除済み除外） .where(and(eq(items.listId, id), isNull(items.deletedAt)))
削除済み含む取得 ?includeDeleted=true クエリパラメータを GET /api/lists/:id/items に渡す
ソフトデリートの実装コード例 
// 削除 (DELETE /api/lists/:id/items/:itemId)
await db
  .update(items)
  .set({ deletedAt: new Date() })
  .where(eq(items.id, itemId));

// 復元 (POST .../restore)
await db
  .update(items)
  .set({ deletedAt: null })
  .where(eq(items.id, itemId));

// 公開ページ: 削除済み除外
const activeItems = await db
  .select().from(items)
  .where(and(eq(items.listId, listId), isNull(items.deletedAt)));

// 登録ページ: 削除済みも含む (?includeDeleted=true)
const allItems = await db
  .select().from(items)
  .where(eq(items.listId, listId));

db:reset の効能と危険性
データ消滅注意 — pnpm db:reset はローカルの D1 データと全マイグレーション履歴を削除する。プロダクション DB には絶対に触らない。

db:reset が実行するコマンド:

rm -rf migrations .wrangler/state/v3/d1
pnpm db:generate   # schema から再生成
pnpm db:migrate    # ローカル D1 に再適用

主な用途: 開発中に溜まったマイグレーション履歴をリリース前に 1 本にまとめるとき（/db-reset スキルが自動実行）。
