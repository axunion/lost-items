図で全体像を掴むための1枚。正確な仕様やAPI詳細はコード/README/CLAUDE.mdを参照。設計判断の理由は overview.md。

システム構成

補足
  • Astro SSR と Hono API は同一 Cloudflare Worker 上で動作し、どちらも D1 に直接アクセスする（createDb() をそれぞれの側で呼ぶ）。
  • 画像は R2 に置くが直URLは公開せず、Hono の /api/images/:key 経由で配信する。

アクセス階層

補足
  • id と publicId は別値。公開ページに露出する値（画像URLを含む）は必ず publicId を使い、id を使うと来場者が管理URLを推測できてしまう。
  • ADMIN_TOKEN はルームの「存在を知る」ことだけを守る。リンクを既に持っている相手を止める仕組みではない。

ドメインモデル

補足

items は復元可能なようにソフトデリート、lists は削除時にR2画像も連鎖削除するため物理削除。厳密なフィールド一覧は src/server/db/schema.ts が正。
