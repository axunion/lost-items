Lost Items

イベント・施設向け落とし物管理 Web アプリ — 実装ドキュメント

Astro 6 SSR SolidJS Hono Drizzle ORM Cloudflare Workers D1 (SQLite) R2 TypeScript

「ルーム」単位で落とし物を管理するアプリ。スタッフ向けの登録ページと来場者向けの公開ページを URL で共有し、アカウント不要で即利用できる。

アーキテクチャ

Astro SSR と Hono API はどちらも同一の Cloudflare Worker 上で動作する。Astro SSR は D1 に直接アクセスし、Hono API は D1 と R2 の両方を使用する。

ドメインモデル

★SD = ソフトデリート。items のみ適用。lists は物理削除。

設計上の重要な前提と判断
  • 認証なし・CSRF なし — ルーム ID (UUID) が共有鍵として機能する。URL を知っている人なら誰でもアクセス・編集可能。機微な用途には向かない。
  • ソフトデリートは items のみ — 削除済みアイテムは deleted_at に日時を記録し、復元を可能にする。lists は R2 画像の連鎖削除が必要なため物理削除。
  • createDb は 2 箇所から呼ばれる — Hono ルートは c.env.DB、Astro SSR ページは cloudflare:workers の env を経由して渡す。
  • zod スキーマはインライン定義 — フロントエンドとバックエンドで共有する型/スキーマファイルはなく、各 Hono ルート内に zod を直接書いている。
  • AppType は未使用 — Hono RPC 対応の型エクスポート (src/server/index.ts) があるが、現状クライアント側からは利用していない。
  • 公開ページは SSR-only — /[id]/room.astro は client:* ディレクティブを使わず、完全にサーバー側でレンダリングされる静的 HTML を返す。
  • 画像は R2 に保存し Hono 経由で配信 — R2 の直接 URL は公開せず、/api/images/{key} を通じてアクセスする。Cache-Control: public, max-age=31536000 で長期キャッシュ。
